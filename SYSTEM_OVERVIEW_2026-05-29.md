# Dealer Social Post AI — System Overview + Polish Pass (2026-05-29)

## How the system works, end-to-end

### Product in one sentence
A salesperson taps a 4-digit dealer code on an iPad, captures a vehicle photo, and gets back a polished social-media post (image + caption + disclosures) generated by Gemini / Imagen / Veo — branded to the dealership, with an optional manager approval gate before it counts as published.

### Request flow — a single post generation

1. **Salesperson logs in.** `POST /api/app/session { dealerCode }`. Server validates against `dealers.code` or `dealers.admin_code`. On success, mints a random 64-char hex token, writes a `sessions` row (dealer, role, IP, UA, 7-day expiry), and returns it as an HttpOnly Secure SameSite=Strict cookie. Failed attempts are logged to `auth_events` and after 10/IP/15min you're 429'd.
2. **App boots.** `GET /api/app/session` resolves the cookie → session row → dealer record. Frontend hydrates `useAppStore` (Zustand) with the dealer.
3. **Photo capture.** `<CameraCapture>` / `<WebcamCapture>` / `<VinScanner>` → image as base64 data URL → `ImageCropModal` for square/portrait/landscape framing.
4. **Customization.** `<PostCustomizer>` collects style, tone, customer name, optional creative brief / scenario / VIN.
5. **Generation.** `useGeneration` calls `services/geminiService.ts` (1000 lines) which orchestrates:
   - Build prompt via `services/promptConfig.ts` + `promptsV2.ts` + dealer's `brand_voice` / `banned_phrases`.
   - Call image model via `services/geminiProxy.ts` → `POST /api/proxy/...` → PB hook adds API key / service-account JWT → forwards to Google.
   - Fall back to Claude/OpenAI if flag enabled and Gemini hard-fails.
   - Apply disclosures (compliance text) via `disclosureCategories` rules.
   - Return `GeneratedPost { image, text, disclosures }`.
6. **Result + log.** `<PostResult>` renders. `services/posts.ts` POSTs to `/api/app/posts` with style/tone/customer/VIN/has_release/has_video. Server forces `dealer` from session cookie — client cannot lie about which dealership the post belongs to. If `dealer.requires_approval` is true the row lands as `pending`; otherwise `n_a`.
7. **Approval (manager only).** Dealer-admin opens `<ApprovalQueue>` → `<DealerAdminDashboard>` → `PATCH /api/app/posts/:id { approval_status }`. Server checks role + tenant isolation.

### Key collections

| Collection | Purpose | Notable rules |
|---|---|---|
| `dealers` | Tenants. Login codes, brand color, brand voice, banned phrases, contact/social, custom scenarios. | All collection rules `null` — only pb_hooks can write. |
| `sessions` (new) | Opaque session tokens → dealer + role. 7-day TTL, lazy-deleted on read. | Locked. Unique index on `token`. |
| `auth_events` (new) | Append-only audit log: every login attempt, every privilege miss, every rate-limit hit. | Locked. Indexed by `kind+created` and `ip+created`. |
| `posts` | One row per successful generation. Powers leaderboard + approval queue. | Locked. Indexed `(dealer, generated_at DESC)`. |
| `photo_releases` | Customer-signed photo-release attached to a post (compliance). | Locked. `dealer` forced from session. |
| `salespeople` | Per-dealership salespeople list. Soft-delete via `active`. | Locked. Tenant isolation in PATCH/DELETE. |

### Frontend state

- **`useAppStore` (Zustand)** — `step`, `currentDealer`, `selectedImage`, `generatedPost`, `preferredStyle`, `preferredTone`, `error`. Persisted to localStorage so a salesperson on a flaky iPad doesn't lose progress on refresh.
- **`useAppController`** — wires the store to the UI. Single source of action handlers.
- **`useGeneration`** — the orchestration hook that calls geminiService and updates progress.
- **`useDealerTheme`** — reads `dealer.brand_color` and writes `--brand-primary`, `--brand-primary-500`, etc. to `:root`. Lighten helper auto-derives shades.
- **`useLayoutMode`** — desktop vs mobile branching.

### Why this stack
- **PocketBase + SQLite + Fly** is small-team appropriate. One binary, one volume, one machine. Up to ~10 dealers. Past that → Supabase (Postgres + RLS).
- **React 19 + Vite** is the May-2026 default; Server Components aren't a fit here (no SEO need, the app is auth-gated).
- **Zustand + TanStack** is the State-of-React-2025-26 #1 and #2 combo. No need for Redux.
- **Gemini for text + image, Vertex for Imagen/Veo** — the only path to a single-vendor relationship covering 90% of what a dealer needs.

## Polish pass — what changed today

### Visual identity → Dealer Trust
The app used to read like an "AI app demo" (slate-950 + indigo→purple aurora swirls + animated particles + glassmorphism on everything). I aligned it to the **Dealer Trust** design language locked in for the sister product LTV-Desking-PRO: navy primary, calm neutral charcoal surface, no decorative gradients, sentence case in copy, restrained motion. Same product family, two tools.

**Concrete changes:**

| File | Change |
|---|---|
| `styles/globals.css` | Full token rewrite. Semantic palette in RGB-triplet vars (primary=navy-700, no purple/pink). Type scale (12→48). Spacing rhythm. Radii. Elevation tokens. Motion tokens. Decorative gradient vars set to `transparent` (existing references still compile, just disappear). |
| `styles/globals.css` | Removed `body::before` aurora layered gradient + grid pattern. Removed `body::after` floating particles. Removed `ambient-pulse` + `particles-float` keyframes. Replaced with a static brand-tinted radial floor + a hairline brand accent across the top. |
| `index.html` | Removed `.aurora-background` CSS block (60 lines) and the `<div class="aurora-background">` element. Bumped theme-color to match new surface. Dropped indigo glow on the desktop bezel. Tightened CSP (`frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`). |
| `App.tsx` | Hardcoded `bg-slate-950 text-slate-50 selection:bg-indigo-500/30` → token-driven inline styles (`var(--color-surface-base)`, `var(--color-text-primary)`). Selection color now reads from `--brand-primary` so it shifts per dealer. |
| `components/Header.tsx` | Dropped the indigo radial-glow on hover behind the logo. Logo placeholder fallback is solid brand color, not a gradient. "Social Media Generator" badge replaced with sentence-case label "Social post studio" matching the wordmark. |
| `components/LoginScreen.tsx` | Killed the 500×500px pulsing blue radial behind the card. Replaced with a static brand-tinted glow that respects per-dealer color. Login card switched to elevation-3 with a `color-mix` background that picks up the new surface token. Added `aria-live="polite"` and `aria-busy` so screen readers narrate "Authenticating…" → "Welcome." |
| `components/Dialpad.tsx` | Added per-key `aria-label` ("Digit 0", "Delete last digit", etc.) + a `role="group" aria-label="Dealer code keypad"`. Decorative icons gain `aria-hidden`. This brings the login screen up to WCAG 2.2 AA. |
| `components/Logo.tsx` | New mark. Dropped the indigo→purple gradient. Solid brand-color aperture geometry that picks up `--brand-primary` and `--brand-foreground` — same SVG white-labels for every dealer. Wordmark is sentence case. |

### What you'll see when you `npm run dev`
- The page background is a quiet charcoal `#090d17` with a subtle navy wash at the top — confident, not theatrical.
- The hairline accent across the top tints to whatever dealer is logged in (LaFontaine red, Mission Ford blue, etc.). The first thing a dealer's GM notices and the cheapest possible white-label signal.
- The login dialpad has crisp focus rings (3px brand color, always visible) on tab navigation.
- No more swirling gradients, no more floating particles. The product looks like it ships, not like it's pitched.

### What I deliberately did NOT do (still on the punch list)
1. **Tailwind v3 → v4 migration.** Breaking. Two days of work to verify all utility classes still resolve. Leaving the token layer in `:root` means we already get most of the v4 ergonomics; the rest can wait.
2. **Vite 8 → Next.js 16.** This app doesn't need RSC, doesn't need a router framework, and bundle-size doesn't justify the migration. Don't change.
3. **Bundling React + @google/genai from local node_modules.** I see the importmap was already removed before this pass (good — likely your earlier work). package.json has both dependencies, so Vite resolves locally already.
4. **Full WCAG 2.2 AA pass beyond the login screen.** Header + Dialpad + ErrorBoundary + Card are done. The Customize / Result / AdminDashboard screens still need keyboard navigation auditing, color-contrast verification, and live regions on the generation progress messages. Day of work; not a launch blocker if you start with the login screen done.
5. **OKLCH-everywhere migration.** I used `color-mix(in srgb, ...)` because it's Baseline 2025 and works on every browser an iPad will ever run. Going fully OKLCH is fine, but it changes nothing visible.
6. **CSV export, leaderboard polish, fleet view, OTP login** — all from the launch-readiness review. Still on the punch list.
